# Commencer avec Codojo

Ce guide vous accompagne de la création de votre compte jusqu’à votre première soumission acceptée. Comptez une quinzaine de minutes pour l’ensemble du parcours.

## 1. Vérifier les prérequis

**Pour l’application Web**, un navigateur récent suffit.

**Pour la CLI**, il vous faut :

- **Node.js 22 ou une version ultérieure**, avec npm. Vérifiez avec `node --version`.
- **Un émulateur de terminal moderne** : GNOME Terminal, Konsole, kitty, Alacritty, iTerm2, Windows Terminal… La CLI repose sur des symboles Unicode standards et s’affiche correctement dans tout terminal récent.

> Aucune police spéciale ni configuration avancée du terminal n’est requise. Un environnement confortable (police lisible, thème sombre) améliore le confort de travail, mais n’est pas nécessaire pour utiliser Codojo — comme pour la plupart des outils en ligne de commande actuels.

## 2. Ouvrir Codojo

Rendez-vous sur [codojo.ekodevs.com](https://codojo.ekodevs.com). Créez un compte ou connectez-vous avec votre compte existant.

## 3. Choisir un exercice

Le catalogue présente les exercices disponibles, leur difficulté (Facile, Moyen, Difficile) et leur état de progression. Commencez par un exercice déverrouillé et lisez toute la consigne avant d’écrire du code.

## 4. Comprendre le contrat

Identifiez les paramètres attendus, la valeur de retour, les cas limites et les contraintes. Une solution correcte doit respecter le contrat fonctionnel, pas seulement réussir un exemple.

Si l’exercice porte sur une notion que vous ne maîtrisez pas encore, consultez [les notions au programme](/docs/notions/) : chaque famille de compétences dispose d’une page avec exemples et pièges classiques.

## 5. Tester votre solution

Exécutez les tests depuis l’interface de l’exercice. Un test en échec indique le résultat obtenu et vous aide à localiser le comportement à corriger. Vérifiez aussi les cas vides, les valeurs inattendues et les entrées de grande taille.

## 6. Soumettre

Lorsque les tests locaux sont satisfaisants, envoyez votre solution pour la validation officielle. Une soumission est évaluée par le serveur et contribue à votre progression si elle est acceptée. Le détail est décrit dans [le guide de soumission](/docs/submitting/).

## Conseils de travail

- Faites une modification à la fois.
- Gardez les fonctions courtes et nommées.
- Testez les cas limites avant d’optimiser.
- N’envoyez jamais de token ou de secret dans le code d’un exercice.
