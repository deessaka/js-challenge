# Domain Docs

Le dépôt utilise une documentation mono-contexte.

## Sources à lire avant une intervention

- `CONTEXT.md` pour le vocabulaire métier canonique ;
- les ADR pertinentes dans `docs/adr/` pour les décisions architecturales.

L’absence d’un document ne bloque pas l’exploration. Les nouveaux termes et ADR sont créés uniquement lorsqu’une décision réelle le justifie.

## Vocabulaire

Les issues, spécifications, tickets, tests et propositions utilisent les termes définis dans `CONTEXT.md`. Les synonymes marqués `_Avoid_` ne doivent pas être réintroduits.

## Conflits architecturaux

Toute proposition contredisant une ADR existante doit signaler explicitement le conflit et expliquer pourquoi la décision mérite d’être réouverte.
